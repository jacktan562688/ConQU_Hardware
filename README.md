## 第一次怎么用

1. 打开 [首日诊断](logs/2026-11-09.md)，先独立答题并填实际耗时。
2. 每次学习结束前留 10 分钟，记录一条理解变化、一条证据和一个下次动作。状态写到 [掌握情况](progress.md)。
3. 截图、源文件和报告保存到 evidence 对应子目录。先保留原件，再在日志里用相对链接指向它，例如 `../evidence/rc/2026-11-21_rc-step.png`。附件准备好后再把路径写成链接。
4. 每周按 [周复盘模板](templates/review.md) 生成复盘，挑出三条最值得复测的内容。原来的错误和失败尝试保留，补一条带日期的纠正。

这是普通 Markdown 文件夹，用任意 Markdown 编辑器即可阅读。使用 Obsidian 时，选择「打开文件夹作为仓库」，指向 `D:\CQU\ConQU\Hardware-KB`。新文件保留 UTF-8，链接使用相对路径。日期按北京时间。

记录原则是把**原始过程**和**已验证结论**分开。日志记录当时真实的想法和操作，知识卡标明适用条件，实验记录交代别人如何复现。队内材料用标题和链接索引，个人笔记与截图留在本地。

## GitHub 同步

本目录用 Git 记录学习版本。每次更新后，检查 `git status --short` 和待提交差异，只暂存本次学习文件，提交后推送到绑定的私有仓库。首次连接需要个人账号下的空私有仓库。

考勤目录、原始证据、Obsidian 配置及 `private/` 留在本地。部分指向本地台账的链接只在本地知识库可打开。适合保留在远端的项目证据经检查后可放在 labs 子目录。
